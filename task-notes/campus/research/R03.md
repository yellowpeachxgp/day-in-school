# R03 天气数据源调研

> 调研日期：2026-11-26（Asia/Shanghai）  
> 范围：只读调研；不改业务代码。候选只覆盖公开文档可核验的通用天气 API；不评估爬虫、逆向私有接口或未经授权的网页接口。  
> 证据口径：许可证、署名、配额只采信官方原文；无法从官方公开页确认的写「未知」。本文不是法律意见，实施前仍需维护者复核当时有效的条款。

## 1. 结论摘要

1. **默认免 Key 来源推荐：MET Norway Locationforecast 2.0**。理由不是它在中国最准，而是它在免 Key 候选里许可边界最稳：公开数据许可证为 NLOD 2.0 与 CC BY 4.0，未见 NonCommercial 限制；服务按任意经纬度提供全球 9 天预报，因此中国城市坐标可用。代价是：中国属于「rest of the world」，官方文档写明 6 小时更新、 identical requests 不应快于 3 小时一次，且大部分精细化数据在北欧；中国本地准确率和预警能力未知。
2. **Open-Meteo 是技术适配度最高的免 Key 候选，但不能无条件默认**。它有降水概率、全球任意经纬度、CMA GRAPES Global 模型和中文地理编码；本次对郑州做了轻量连通性验证并返回数据。然而其免费 API 明确限非商业用途。项目核心 App 虽拒绝广告，但既有云端 🍑/增值服务是否使整体构成订阅或商业用途**未知**；在未确认前，把 Open-Meteo 作为无条件默认有合规风险。若维护者确认非商业属性成立，Open-Meteo 可成为更优默认；否则只能走付费/自托管/用户自带商业 Key。
3. **BYOK 首选：和风天气（QWeather）**。它要求 JWT 或 API KEY，天气与基础服务每月前 50,000 次请求为 0 元，实时天气按经纬度 1 公里分辨率覆盖全球任意地点，并明确要求显示「和风天气/QWeather」及响应 `metadata.attributions` 中的所有归因。它最适合作为中国增强源。OpenWeather 可作为第二 BYOK 源。
4. **天气只能作为带可信等级的条件输入**。过期、网络失败、许可/Key 失效、缺降水字段或 Provider 不可用时，自动化条件必须判定为 UNKNOWN，不得触发「带伞」等动作；试运行结果必须显示 Provider、获取时间、数据有效时间和署名。

## 2. 判断口径

- 「中国城市覆盖」分两层：**天气预报是否覆盖中国境内经纬度**，以及**是否提供中国城市/行政区搜索**。自动化只需要校园或校区参考坐标，不应为了天气查询获取用户精确定位。
- 本项目使用场景是低频自动化条件（如早八带伞、跨校区通勤），不是完整天气 App；因此优先级为：许可可复用 > 隐私与本地优先 > 降水/天气现象字段足够 > 中国本地精度 > 附加功能（预警、空气质量、分钟降水）。
- 不把中心云代理作为默认：它会把可用性与隐私边界复杂化。默认使用学校包/Campus Graph 中的校区参考坐标；若未来接入精确位置，必须单独征求同意。

## 4. 分项证据与原文链接

### 4.1 MET Norway Locationforecast 2.0（默认推荐）

- 覆盖：官方 [Locationforecast 文档](https://api.met.no/weatherapi/locationforecast/2.0/documentation)写明 “Weather forecasts for any location on earth”，对任意坐标提供未来 9 天预报；“most data for the Nordic region”；Nordic 每小时更新，rest of the world 每 6 小时更新；相同请求 Nordic 不应快于 30 分钟、rest of the world 不应快于 3 小时。官方 [OpenAPI schema](https://api.met.no/weatherapi/locationforecast/2.0/swagger.json)的 `ForecastTimePeriod` 包含 `precipitation_amount` / `precipitation_amount_min` / `precipitation_amount_max` / `probability_of_precipitation` / `probability_of_thunder` 字段；但这些字段在不同端点、地区和时间步是否稳定返回，仍需在 W2-03 用夹具和线上 smoke 分开验证。
- 许可与署名：官方 [Licensing and Data Policy](https://api.met.no/doc/License)写明除非另有说明，数据和产品采用 NLOD 2.0 与 CC BY 4.0；应 credit “The Norwegian Meteorological Institute, shortened MET Norway”，示例为 “Data from MET Norway” / “Based on data from MET Norway”。
- 配额和直连限制：官方 [Terms of Service](https://api.met.no/doc/TermsOfService)要求总流量低于 20 requests per second、缓存响应、不要重复相同请求；移动应用/浏览器在流量增长后应使用缓存代理。条款原文对低量场景明确列举的是 simple cross-origin Javascript requests 和 direct image links，**Android 原生直连不是该句明确展开的场景**；实施时必须由维护者复核，或在用户量增长后改为按校区粗坐标缓存的代理。直接调用会记录用户 IP 与坐标，官方建议使用户匿名化的代理。条款还要求坐标最多截断到 4 位小数。
- 特别风险：同一 [Terms of Service](https://api.met.no/doc/TermsOfService)在 2026-10-21 变更中加入 “Use of AI agents”：条款必须由有权限的人类阅读、理解并接受。**因此本调研不能代替维护者接受条款；W2-03 实施前必须把该确认列为前置任务。**
- 为什么仍推荐：在免 Key 候选中，它没有发现 NonCommercial 限制，许可文本直接、署名简单；对「是否有降水/天气现象」的低频自动化足够。必须把预报视为粗粒度外部数据，不得宣称中国本地准确度已经验证。

### 4.2 Open-Meteo（技术最佳，但默认受商业属性待决约束）

- 免费限制与配额：官方 [Terms & Privacy](https://open-meteo.com/en/terms)写明免费非商业 API 少于 10,000 calls/day、5,000/hour、600/minute；只能用于非商业目的；带订阅或广告的网站/App 被列为商业用途，商业用途或更多请求应订阅 API plans。
- 许可与署名：官方 [Licence](https://open-meteo.com/en/licence)写明 API data 采用 CC BY 4.0，必须给 appropriate credit、链接 license、说明变更；并明确要求在展示 Open-Meteo 数据的位置附近加入链接，例如 `<a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>`。
- 中国与城市覆盖：官方 [Weather Forecast API 文档](https://open-meteo.com/en/docs)说明默认 best_match 为全球位置选择模型，全球骨干含 DWD ICON、NOAA GFS、ECMWF IFS；模型表列出 CMA GRAPES Global：中国气象局，15 km，10 天，每 6 小时更新。官方 [Geocoding API](https://open-meteo.com/en/docs/geocoding-api)写明可 globally in any language 搜索位置，位置数据基于 GeoNames。
- 轻量连通性验证（不是准确性验证，时间 2026-11-26T14:33Z）：
  - `api.open-meteo.com/v1/forecast`，郑州坐标、`best_match`：HTTP 200，`timezone=Asia/Shanghai`，48 个小时点，返回 `weather_code`、降水与降水概率字段。
  - 同一坐标指定 `models=cma_grapes_global`：HTTP 200，48 个小时点。
  - `geocoding-api.open-meteo.com/v1/search?name=郑州&countryCode=CN&language=zh`：HTTP 200，返回“郑州 / 河南 / 郑州市”，坐标约 34.75778,113.64861。
- 决策风险：项目是否存在订阅/商业用途未知。若后续确认项目整体为非商业（无订阅、无广告；自愿捐赠在 Open-Meteo 条款示例中允许），Open-Meteo 比 MET Norway 更适合作为默认，因为它有降水概率、CMA 模型和更细的更新；在确认前不做无条件默认。

### 4.3 和风天气 QWeather（BYOK 首选）

- Key：官方 [开始使用](https://dev.qweather.com/docs/start/)与[身份认证](https://dev.qweather.com/docs/configuration/authentication/)说明需要创建项目/凭据，支持 JWT 与 API KEY，并使用独立 API Host。
- 配额/费用：官方 [按量计费定价](https://dev.qweather.com/docs/finance/pricing/)写明天气和基础服务按请求阶梯计费，每月 0–50,000 次为 CNY 0，之后 950,000 次为 CNY 0.0007/次等；[计费方式和支付](https://dev.qweather.com/docs/finance/billing-and-payment/)说明按量后付费。
- 署名与许可：官方 [注明来源](https://dev.qweather.com/docs/terms/attribution/)要求在产品中清晰、完整显示 “和风天气” 或 “QWeather”，以及 API 响应 `metadata.attributions` 中的所有内容（包括数据提供方名称、声明、URL 等），不得删减、改写；[使用限制](https://dev.qweather.com/docs/terms/restriction/)说明未注明来源可能停止服务；服务条款入口见 [服务条款](https://dev.qweather.com/docs/terms/tos/)，其链接的开发者许可协议为 <https://www.qweather.com/terms/developers-eula>。
- 中国覆盖：官方 [实时天气](https://dev.qweather.com/docs/api/weather/weather-current/)写明按经纬度 1 km 分辨率、覆盖全球任意地点、分钟级更新；[常见城市列表](https://dev.qweather.com/docs/resource/location-list/)写明提供全球 15 万个城市和多种 POI 的天气数据服务。
- 适配：字段、归因和中国本地能力最适合增强；但 Key 必须属于用户本人/组织，不能内置项目方统一 Key，云端不代理、不存储。

### 4.4 OpenWeather（第二 BYOK 候选）

- Key 与配额：官方 [Pricing](https://openweathermap.org/price.md)写明 Free weather API access 包含 60 API calls/minute、1,000,000 calls/month，覆盖 Current Weather、3-hour Forecast、Air Pollution、Weather Maps、Geocoding；[One Call API 3.0](https://openweathermap.org/api/one-call-3.md)说明该订阅每天 1,000 次免费，超出按次付费。
- 许可与署名：官方 [Full price / License](https://openweathermap.org/full-price.md)写明自助计划采用 ODbL，商业使用允许；[FAQ attribution](https://openweathermap.org/faq.md)要求 Free–Professional 计划在可见位置放置 “Weather data provided by OpenWeather”、官网链接和 OpenWeather logo。Full price 还说明只有构建、重构、组合或丰富并对外提供自己的天气数据集/API 时才触发派生数据库 Share-Alike；本项目的终端短期缓存不应设计为对外再分发数据库。
- 覆盖：官方 [Geocoding API](https://openweathermap.org/api/geocoding-api.md)支持城市名正/逆地理编码；[Pricing](https://openweathermap.org/price.md)写明 One Call 全球经纬度覆盖。

### 4.5 高德天气（不首批推荐）

- 官方 [天气查询文档](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)：必须申请 Web 服务 API Key；按 `adcode` 查询目标区域当前/未来天气；实况每小时更新多次，预报每天约 8、11、18 点更新 3 次。
- 官方 [产品定价/基础服务配额](https://lbs.amap.com/upgrade#price#base_service_price)：天气预报查询 30 元/万次；天气查询月配额为个人认证开发者 5,000、经评估的非商业用途 5,000（1 年）、企业技术服务许可 9,000,000；QPS 在控制台查看。
- 官方 [高德地图开放平台服务协议](https://lbs.amap.com/home/terms/)：个人研究学习与商业/组织使用分界明显；不得删除或遮挡版权、商标或其他所有权声明；“高德地图”字样标志仅可用于说明应用使用了本服务，不能暗示高德赞助或认可。
- 适配问题：只按行政区 `adcode`，不是校区坐标级；组织使用许可与付费边界复杂，不适合作为普通用户 BYOK 的首选。

### 4.6 心知天气（不首批推荐）

- 官方 [价格方案](https://www.seniverse.com/pricing)：免费版适合个人开发者，永久免费，国内 370 个主要城市，1 次/秒，10 万次/月；免费数据权限 3 项，逐日天气预报 3 天。开发者套餐标明“不可商用”。
- 官方 [天气实况](https://docs.seniverse.com/api/weather/now.html)：免费用户只返回天气现象文字、代码和气温 3 项；中国城市暂不支持云量和露点温度。官方 [逐日天气预报](https://docs.seniverse.com/api/weather/daily.html)：免费用户只返回 3 天预报。
- 官方 [服务协议](https://www.seniverse.com/terms)：未获得授权不得缓存心知天气数据；获得数据后不得出租、出借、复制、转载、发表、出版或向第三方分发、销售、再授权。未在公开协议中找到明确署名格式，故署名要求记为未知。
- 适配问题：自动化通常需要短时本地缓存以防重复请求，缓存限制需要单独确认；免费城市覆盖和降水字段不足。

### 4.7 彩云天气（暂缓）

- 官方 [彩云天气 API](https://open.caiyunapp.com/%E5%BD%A9%E4%BA%91%E5%A4%A9%E6%B0%94_API)与[一览表](https://open.caiyunapp.com/%E5%BD%A9%E4%BA%91%E5%A4%A9%E6%B0%94_API_%E4%B8%80%E8%A7%88%E8%A1%A8)：使用 Token；小时级和天级预报覆盖全球任意经纬度，分钟级预报覆盖地区包括中国，空气质量覆盖中国全境。
- 未能在官方公开页核验当前免费配额、价格、数据许可证和署名要求；控制台页面只返回客户端渲染外壳。按「不得编造」原则全部记为未知，因此不进入推荐。

## 5. 对 W2-03 `WeatherProvider` SPI 的落地建议

### 5.1 Provider 顺序

1. `MetNorwayWeatherProvider`：默认、免 Key、内置 Provider ID，但不内置任何秘密。首次启用前展示条款/隐私说明与署名；维护者确认接受 ToS，并确认 Android 原生直连符合低量条款（或已提供合规缓存代理）后才合并实现。
2. `OpenMeteoWeatherProvider`：可以先作为**编译存在但默认关闭**的备选实现，或等商业属性确认后再启用；不得静默绕过免费非商业限制。
3. `QWeatherWeatherProvider`：BYOK 增强源，用户粘贴自己的 API KEY 或 JWT 配置；默认关闭。
4. `OpenWeatherWeatherProvider`：第二 BYOK 增强源，默认关闭。

### 5.2 数据与可信模型

- 复用 `SchoolAccountScope` 传递学校/账号/Profile/校区上下文，不另造身份类型。
- 复用 `DataProvenance`：`providerId` 使用 `met-norway` / `open-meteo` / `qweather` / `openweather`；`sourceSystem` 记录 API 名称与版本；`fetchedAt` 记录本地获取时间；`contentRevision` 优先使用上游更新时间/数据时间；`completeness` 反映降水、天气现象、温度是否完整。
- 复用 `VerificationLevel` / `CapabilityState`，不新增等价枚举。仅文档调研和 fixture 测试不得标 `DEVICE_TESTED` 或 `SCHOOL_VERIFIED`；未做真机和真实账号验证时保持更低证据等级（如 `MOCK_TESTED`）并在 UI 中如实显示。
- 每次快照保存 `attributionLines`、`licenseUrl`、`termsUrl`、`validAt/forecastTime`、`cacheExpiresAt`。它们不是可选元数据，而是 Provider 输出的一部分。

### 5.3 隐私、缓存与频率

- 默认位置：学校包或 Campus Graph 的校区参考坐标；不使用精确 GPS。若校区坐标缺失，能力为 `UNSUPPORTED` 或要求用户选择城市/校区，不后台推断。
- MET Norway：rest-of-world 相同坐标请求间隔至少 3 小时，并加随机分钟抖动；坐标最多 4 位小数；自定义 User-Agent 应包含应用名、版本和公开项目联系方式/仓库地址，不能用通用 `okhttp` 或伪造字符串。
- 其他 Provider：即使上游更新更频繁，自动化默认也只按 1–3 小时粒度读取；前台手动刷新可单独限流。
- 不做云端集中缓存作为默认。若未来用户量增长必须代理，只能按校区粗坐标缓存，且重新评估隐私、条款和 Share-Alike/缓存限制。
- BYOK Key 按 Profile 隔离，使用 Android Keystore AES-GCM 保护；不进入备份、日志、诊断、崩溃报告或云端。实现可复用 AI BYOK 的存储模式，但天气 Key 与 AI Key 的用途、同意和清除入口应分开显示。

### 5.4 自动化诚实边界

- 「早八带伞」优先使用降水概率/降水量/天气现象的组合。MET Norway OpenAPI schema 中有 `probability_of_precipitation`，但若目标端点/地区/时间步未稳定返回，则只用降水强度和天气符号；阈值必须可在模板中试运行并解释。
- 数据过期、HTTP 错误、许可未确认、Key 缺失/失效、字段缺失、位置缺失时条件为 UNKNOWN；UNKNOWN 不通过、不触发，并在运行记录写明原因。
- 不得把多个 Provider 的结果混合成同一快照；切换 Provider 后重新记录 provenance 和署名。
- 用户可见的自动化解释、天气卡片或试运行页面必须在相关数据附近展示署名；仅后台触发时也应在规则试运行/运行记录中保留署名与来源链接。

## 6. 待决事项

1. **项目商业属性**：day-in-school + 云端 🍑/增值服务在 Open-Meteo 定义下是否属于非商业？推荐由主代理/用户确认；在确认前默认仍用 MET Norway。若确认非商业，可把 Open-Meteo 提升为默认候选并重做条款复核。
2. **MET Norway 条款接受**：需要有权维护者在实施前阅读并接受 ToS（尤其 User-Agent、缓存、AI agents 条款）；建议记入 DECISIONS。
