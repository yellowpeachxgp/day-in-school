## 0. 结论

1. **现状比描述的要薄。** SDK 的六个 UI 槽位、CLI 四个命令、hello-campus 示例、Android 的 `ExtensionManifestV2Codec` 都确实存在。但同时存在三套互不兼容的「v2 规范」，Android 运行时完全没有接入签名验证，云端注册表只存在内存里，而且全新部署时示例插件根本加载不上（注册表为 0 个）。
2. **有 4 个必须先修的安全问题**：升级时新权限被自动授予；回滚后仍保留新版本的权限；Android 的「添加扩展功能」不经过任何清单和签名校验，直接写数据库；第三方命令什么都不执行，却返回 `executed: true`。
3. **现有测试只覆盖正向流程**：云端 2 个用例和 1 个红队用例，Android 1 个解析用例。契约 CI 是绿的，但示例清单其实不符合契约里的 JSON Schema。
4. **建议**：不另起炉灶，把 issue #43 并入已有的 W6 卡。先统一规范（阶段 0），再补安全底座（阶段 1），然后只落地一种扩展形式，即「声明式卡片 + 数据包」，并配一个官方示例（阶段 2）；开发者工具（阶段 3）和插件目录、自动化（阶段 4）放在后面。

## 4. 分阶段升级方案（全部并入现有卡片，不新开平行体系）

**总原则**
- **保留**：运行时 snake_case 的 `dis-extension/v2` 格式和 6 个槽位，作为 v2 正式版。现有示例、SDK、Android 解析器、测试都基于它，改名的破坏面最大、收益最小。
- **v2.1 只做加法**：新增可选字段、类型和槽位，不改名、不删除已有字段。旧清单原样有效。
- **复用**：Android 的 `core/school-packages`（Ed25519、`PackageVerifier`、`PackageInstaller`、`PublisherKeyRegistry`、`PackageGrantRegistry`），云端的 `plugin-sdk`、`crypto`、错误码、权限目录、已有路由和 operationId。**不新建 Android 插件模块，不新建第二套签名代码。**
- **不做**：远程代码执行（契约 I.6），这也就排除了 issue 里「受限脚本」和「独立进程插件」两个选项。首期唯一的扩展形式是**声明式卡片 + 声明式命令 + 签名数据包**。

### 阶段 0 · 统一事实源（并入 INF-02，新增卡 W6-00）

| 工作 | 要点 |
|---|---|
| 一份规范 | 把 `plugin-extension-v2.schema.json` 改写为**准确描述运行时格式**；SDK 的 `validatePluginManifest` 先跑 JSON Schema 再做语义检查，不再维护手写的字段规则 |
| 一份槽位表 | 槽位、类型、权限的权威来源统一为 `host-api-matrix.yaml`（v2 = 现有 6 个槽位）；SDK 和 Android 解析器都从契约生成或在测试中逐项比对 |
| 共享夹具 | 新建 `contracts/fixtures/plugins/{valid,invalid}/*.json`（至少 30 个：每个必填字段缺失、每种非法值、Zip-Slip、非 HTTPS、未知权限、未知槽位、host API 越界）；**云端和 Android 的测试读取同一批夹具，结论必须一致** |
| 示例可加载 | 在 `.gitignore` 中放行 `!examples/**/plugin-signing-public.key`（只放行公钥）；把 `app.mjs:168` 的空 `catch` 改为写日志，并在 `/readyz` 或 `/api/v1/features` 中报告参考插件的加载状态 |
| 诚实文档 | `PLUGIN_SDK_GUIDE.md` 补齐：格式字段表、6 个槽位的含义和渲染位置、权限目录、生命周期状态机、**不执行插件代码**的边界、密钥管理；示例的 `dist/index.mjs` 标注为「仅供宿主内置示例使用的 handler，第三方插件不会执行」 |

### 阶段 1 · 宿主安全底座（W6-01 拆出 W6-01a）

| 工作 | 要点 |
|---|---|
| 权限确认 | 安装和升级时计算 `permissions` 差集；有新增权限时，安装状态变为 `PENDING_PERMISSION_REVIEW`，旧版本继续生效，直到用户确认；`granted_permissions` 是「用户批准的集合 ∩ 当前版本声明的集合」 |
| 回滚 | 回滚时把授权收缩为 `granted ∩ 目标版本声明`；目标版本不再存在或签名失效时拒绝回滚 |
| 撤权 | 新增 `REVOKE_PERMISSION` 生命周期动作，可以逐项撤权；依赖被撤权限的命令返回 `PLUGIN_PERMISSION_DENIED` |
| 信任根 | 云端从配置加载发布者公钥清单（`publisher → 公钥`），**broker 不再持有私钥，也不再每次启动随机生成**；生产环境只接受清单中的发布者；非生产环境的抢注规则写进文档 |
| 持久化 | 新的 SQL 迁移（编号由主代理分配），在 `installed_plugins` 的基础上补齐 `plugin_versions`（manifest、签名、发布者）和 `plugin_installations`（`cloud_user_id, school_id, plugin_id, active_version, previous_version, status, granted_permissions`）；broker 改为由存储驱动 |
| 作用域 | 安装记录按 `(cloud_user_id, school_id)` 区分；Android 使用已有的每身份独立数据库（`installed_extension_plugins` 已天然按身份隔离），补上 `schoolId` 字段 |
| 命令语义 | 第三方命令只允许几种声明式类型：`open_host_route`（宿主白名单路由）、`open_url`（必须在 `allowed_origins` 内）、`show_data`（读取插件自带的签名数据）；未知类型返回 `PLUGIN_COMMAND_UNSUPPORTED`，**不再返回 `executed: true` 的回显** |
| 故障隔离 | 每个插件独立计数错误；超过阈值自动转为 `DISABLED` 并记录原因；新增管理端 kill switch（复用已有 `admin` 审计事件） |
| 卸载清理 | 卸载时删除该插件在宿主中的全部数据（`storage.scoped` 分区、授权记录、缓存），并写审计事件。`storage.scoped` 在实现之前从默认模板中移除，并在权限目录中标为保留 |
| Android 安装链路 | 删除「添加扩展功能」的手填对话框（S3）。安装只走一条路径：导入签名包 → `ExtensionManifestV2Codec` 解析 → `PackageVerifier` 用 `PublisherKeyRegistry` 验签和验摘要 → `PackageInstaller` 原子写入 → `PackageGrantRegistry` 记录授权。`installed_extension_plugins` 只允许安装器写入，JSON 用序列化器生成 |
| CLI 卫生 | `init` 把私钥写到 `~/.dis-plugin/keys/`，并在插件目录生成 `.gitignore`；`sign` 读取产物前先做安全路径检查 |

## 5. Agent 验收标准

> 规则沿用 MASTER_PLAN §14.3：在开发机上执行（`cis-gate`）；零容错；`skipped`、`flaky`、重试后才通过、超时一律按失败处理；由没参与开发的验收子代理执行，第二个验收子代理复核全部安全类条目（AC-1x）。每一条都要写明测试名、命令和日志路径。

### 阶段 0

| 编号 | 验收标准 | 判定方法 |
|---|---|---|
| AC-01 | 两个示例清单和 CLI `init` 生成的清单都通过 `plugin-extension-v2.schema.json` 校验 | 契约 CI 新增「示例按 Schema 校验」步骤；故意删除一个必填字段时 CI 变红 |

### 阶段 1（安全类：需要两个独立验收子代理）

| 编号 | 验收标准 | 判定方法 |
|---|---|---|
| AC-11 | 升级新增权限时不会自动授予 | 安装 v1（1 项权限）→ 安装 v1.1（4 项权限）：状态为 `PENDING_PERMISSION_REVIEW`，`granted_permissions` 仍为 1 项，生效版本仍为 v1；确认后才变为 4 项 |
| AC-12 | 回滚会收缩权限 | 接上一条，确认后回滚到 v1：`granted_permissions` 等于 v1 的声明 |
| AC-13 | 逐项撤权立即生效 | 撤销 `network.request` 后，带 origin 的调用返回 403 `PLUGIN_PERMISSION_DENIED` |
| AC-14 | 跨用户、跨学校隔离 | 用户 A 安装的插件，用户 B 调用返回 403；同一用户在学校 X 安装的插件，在学校 Y 的作用域中不可见 |
| AC-15 | 重启后状态不丢 | 安装 → 重启应用（新建 app 实例，连接同一个测试数据库）→ 安装记录、授权、公钥固定都保留 |
| AC-16 | 信任根 | broker 中不存在私钥字段；未在发布者清单中的公钥在生产模式下被拒绝；在非生产模式下的行为与文档一致 |
| AC-17 | 第三方命令不再伪装执行 | 未知命令类型返回 `PLUGIN_COMMAND_UNSUPPORTED`；任何响应中都不会出现回显的请求 payload；`open_url` 指向 `allowed_origins` 以外的地址时被拒绝 |
| AC-18 | 故障隔离 | 模拟连续 N 次失败后插件自动 `DISABLED`，原因写入审计；其他插件和宿主接口不受影响；管理端 kill switch 能立即停用 |
| AC-19 | 卸载清理 | 卸载后，该插件的授权、存储分区、缓存行数为 0，并产生审计事件；再次安装不会读到旧数据 |
| AC-20 | Android 只有一条安装路径 | 静态检查：在 `core/school-packages` 之外，任何代码调用 `upsertInstalledExtensionPlugin` 都会导致门禁失败；「添加扩展功能」手填对话框已删除 |
| AC-21 | Android 拒绝非法包 | 篡改清单、篡改产物、未知发布者、Zip-Slip、非 HTTPS origin、host API 越界，各有一个测试，全部抛出对应的 `PackageError`，且 `installed_extension_plugins` 行数不变 |
| AC-22 | Android 原子性 | 在安装中途注入故障（写入第 k 个文件时抛异常）：旧版本保持可用，数据库和文件存储都没有半成品 |
| AC-23 | 擦除链路 | 执行身份数据擦除后，插件安装表、授权表、插件存储均为 0 |
| AC-24 | CLI 卫生 | `init` 后插件目录中不存在私钥，存在 `.gitignore`；`sign` 遇到 `../x` 产物路径时报错退出 |
