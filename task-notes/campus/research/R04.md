## 1. 一页结论

1. **推荐算法**：:core:solver 首期实现**纯 Kotlin、位集加速的自定义 CSP 求解器**：预处理编译候选教学班 → 前向检查与学分界传播 → MRV/degree 变量排序的回溯搜索 → 用非负整数软成本做分支定界 → 最多返回 5 套可解释方案。无解时，复用同一个「可行性判定器」作为 QuickXplain 的一致性 oracle，输出**按包含关系极小、且按用户可放松优先级排序的冲突核**及放松建议。
2. **不建议首期嵌入 CP-SAT**：OR-Tools CP-SAT 是成熟整数约束求解器，并明确返回 OPTIMAL / FEASIBLE / INFEASIBLE / UNKNOWN 等状态；但引入它会增加 Android 原生/依赖打包、确定性、大小和解释层集成风险，也不能直接给用户级 QuickXplain 冲突核。它可以作为开发机测试用的**对照 oracle**，不作为首发运行时依赖。参见 [Google OR-Tools CP-SAT 文档](https://developers.google.com/optimization/cp/cp_solver)。
3. **50 个候选教学班小于 2 秒是可设计、可测量但并非无条件保证的目标**：当变量按「课程 offering」而不是布尔候选建模、冲突用位集传播、软成本全部整数化、搜索预算覆盖预处理到排序输出时，50 候选的规模很小；真正风险在指数级最坏情况、弱下界、稀疏但多解实例、以及 QuickXplain 的 oracle 成本。必须用固定合成基准实测，不能只用复杂度推断宣称达标。
4. **QuickXplain 的关键工程设计**：不要在 O(n²) 个两两时段冲突上运行 QuickXplain；两两冲突是候选数据的后果，应留在一致性检查器内部。QuickXplain 的用户级约束集 C 只包含「必选课程、学分上下限、硬时间过滤、硬通勤过滤、是否排除满员/未知容量」等少量可放松约束。背景事实 B 包含课程互斥、已有课表、时段数据和不可违背的学校规则。
5. **诚实边界**：选课沙盘只生成 :core:selection 草稿，不触发任何提交；这与 D1「不追求校方授权、写入默认关闭」和 MASTER_PLAN §6.6 一致。容量、周次、地点或通勤证据不足时，结果必须带不确定性说明，不能把未知当成空闲或可行。

## 2. 仓库内可复用事实

- core/selection 已有教学班、容量三态、草稿、冲突明细和受控提交模型：

## 3. 问题形式化

### 3.1 变量与值

不要把每个候选教学班直接建成 0/1 布尔变量。推荐：

- 每个课程 offering 一个变量 X_o。
- 值域是该 offering 的教学班候选列表；若课程可选而非必选，再加入特殊值 SKIP。
- 必选课程：恰好选一个教学班；选修/候选课程：最多选一个教学班。
- 固定已有课表、个人日程和考试不是变量，而是一组一元占用约束。

这样把「同一课程最多一个班」从大量两两互斥约束变成变量语义，既减少传播成本，也让 QuickXplain 的用户级约束更少。

### 3.2 硬约束

| 类别 | 示例 | 是否可放松 | 处理方式 |
|---|---|---:|---|
| 结构约束 | 同一 offering 最多一班；必选 offering 必须选择 | 通常否 | 变量语义 / 背景 B |
| 时间重叠 | 与已有课表、考试、个人事件或其他候选在同一教学周的同一节次重叠 | 对已有事实否；对“是否避开已有安排”可由用户改 | 位集二元不相容 + unary 预过滤 |
| 周次不确定 | 周次未知时按可能冲突处理，但必须标记 weeksUncertain | 否（这是诚实语义） | 保守传播；结果中标不确定性 |
| 学分范围 | creditRange 下/上限 | 是，用户可改目标 | 全局界传播；QuickXplain 用户级约束 |
| 必选/优先毕业要求 | 用户或培养方案要求选某课程 | 是，但只能由用户确认 | 一元约束；QuickXplain 用户级约束 |
| 容量 | 已知满员是否排除；未知容量是否允许进入方案 | 可作为用户过滤器，不得伪造名额 | unary 预过滤；输出保留容量证据 |
| 通勤可达 | 同一教学周同一天相邻课程之间，课间是否足以完成楼宇间步行 | 缓冲时间可由用户调；物理事实不可改 | 二元不相容；跨校区按矩阵标记 |
| 用户硬过滤 | 不选早八、不选晚课、排除某天 | 是 | unary 预过滤；QuickXplain 用户级约束 |

### 3.3 软偏好与目标函数

软偏好全部转成**非负整数毫分成本**（Long，避免浮点非确定性），总成本越低越好：

- 单候选成本：早八/晚课、教师或班型偏好、容量未知风险展示权重等。
- 成对/日内成本：空档时长、跨楼通勤分钟、每日节次负担、午晚餐被占用。
- 全局成本：上课天数、最早/最晚跨度、每日负担均衡、连续上课时长。

**不要**把「想要的课程」建模成负成本来诱导选择；选修变量有 SKIP 时，负成本会破坏简单下界并增加分支定界风险。应该用学分下限、必选约束或降低该候选的正惩罚表达偏好。

### 3.4 输出语义

- Solutions.ranked：最多 5 套方案，每套附成本分解、约束满足证据、容量/周次/通勤不确定性和确定性 tie-break 规则。
- 必须区分：搜索穷竭证明的最优/前 k 优、预算内找到的当前最优、以及仅构造出的可行解。若预算耗尽，不得把「没找到」写成「无解」。
- Infeasible：只有搜索穷竭或约束传播证明无解后才能返回；附 QuickXplain 冲突核与放松建议。oracle 超时只能返回「无解原因未知/解释超时」。

## 5. 推荐求解器架构

### 5.1 编译与索引

1. 以学期为准建立原子时间格：教学周 1..W × 星期 1..7 × 节次 1..S。基准用 W=20, S=12，共 1680 个原子格，即 27 个 ULong 字。
2. 每个候选教学班编译成：
   - timeBits：所有上课时段的原子位集；
   - slotsByDayAndWeek：用于通勤相邻性检查的展开视图；
   - offeringId、creditMilli、容量、地点/楼宇 ID、来源与数据完整性；
   - unaryCostMilli。
3. 固定已有课表和个人事件编译成 fixedBusyBits，并按事件保留引用，便于解释冲突来源。
4. 预过滤：确定满员且用户选择排除、明确违反硬时间过滤、与固定占用确定冲突的候选直接从值域删除；删除原因必须可回放。
5. 精确重复候选（同 offering、同时段、同地点、同学分、同成本）可合并为一个代表值，但输出必须还原全部教学班 ID；不确定或字段不同的候选不得合并。

### 5.2 冲突矩阵与通勤

- incompatible[a] 是一个候选 ID 位集。若候选 a 与 b 的 timeBits 相交，直接不相容。
- 对同一教学周、同一星期但不重叠的课段，按作息表计算真实间隔分钟。若 gapMinutes 小于 travelMinutes(a,b) + bufferMinutes，也不相容。
- 跨校区不以经验常量猜测；由 TravelTimeMatrix 返回「可达分钟」「课间不可达」或「未知」。未知不能当作可达，结果中必须提示证据不足。
- 全矩阵规模很小：200 候选时，按每行 4 个 ULong 对齐的 200×200 bitset 约 6.25 KiB；每个候选 27 个原子时间字，200 个候选仅约 42.2 KiB。瓶颈不在内存，而在搜索节点数。

### 5.3 约束传播

**必做**：

1. **前向检查**：给一个变量赋值后，用 incompatible[choice] 一次性从其他未赋值变量值域删除冲突候选；任何值域为空立即回溯。
2. **学分界传播**：对每个未赋值域计算最小/最大可能学分（SKIP 为 0）。若 assigned + Σmin 大于 maxCredit 或 assigned + Σmax 小于 minCredit，剪枝；进一步删除会使界不可能成立的值。迭代到不动点。
3. **必选存在性**：必选 offering 值域为空即刻失败；选修 offering 至少还有 SKIP，不会因无候选直接失败，但应在结果中提示没有可排班候选。

**基准后决定**：

- 完整 AC-3/弧一致性能更早发现无解，但一般复杂度高于前向检查。建议在实现中保留开关，用 §7 的 sparse/dense 基准比较：dense 往往受益于强传播，sparse-many-solutions 可能被额外维护成本拖慢。
- conflict-directed backjumping / no-good recording 是后续优化，不作为首期必需。

### 5.4 回溯 + 分支定界

推荐深度优先分支定界，辅以初始 incumbent：

1. **变量排序**：动态 MRV；平局取 degree 大者（与最多其他候选冲突）或更大学分影响者。
2. **值排序**：先低 unaryCostMilli，再低预计通勤/空档成本，最后按教学班 ID 字典序，保证确定性。
3. **初始 incumbent**：先运行一个小预算构造式搜索或 beam search，快速找到若干可行方案。这样分支定界尽早拥有上界；构造结果只作为 incumbent，不声称最优。
4. **下界**：当前成本 + 未赋值必选变量各自最小一元成本 + 可由学分缺口推出的非负下界。所有成对/全局成本若不能安全下界则取 0；宁可弱，不可高估。
5. **top-k**：维护最多 5 套去重方案。第 k 套成本成为上界；若同成本 tie 被剪掉，必须使用固定 tie-break 并在文档中说明。
6. **预算**：用单调时钟检查节点预算和截止时间。预算耗尽返回 BEST_FOUND_BUDGET_EXHAUSTED 或 UNKNOWN，绝不能误报 INFEASIBLE。

示意伪代码：

<pre><code>solve(problem, maxSolutions=5, deadline):
    compiled = compileAndPreprocess(problem)
    if compiled.hasImmediateContradiction: return explain(compiled)
    incumbents = cheapConstruction(compiled, smallBudget)
    search = BranchAndBound(compiled, incumbents)
    outcome = search.searchTopK(maxSolutions, deadline)
    if outcome.exhaustedAndNoSolution:
        return explainInfeasible(compiled, remainingDeadline)
    if outcome.budgetExhausted:
        return solutions(outcome.bestSoFar, completion=BEST_FOUND)
    return solutions(outcome.ranked, completion=PROVEN)</code></pre>

### 5.5 QuickXplain 结合方式

Junker 论文的递归结构（按本文术语改写）：

<pre><code>QuickXplain(B, C):
    if consistent(B ∪ C): return ∅
    if C = ∅: return ∅
    return QuickXplain'(B, B, C)

QuickXplain'(B, Δ, C):
    if Δ ≠ ∅ and not consistent(B): return ∅
    if C = {α}: return {α}
    split C into ordered halves C1, C2
    Δ2 = QuickXplain'(B ∪ C1, C1, C2)
    Δ1 = QuickXplain'(B ∪ Δ2, Δ2, C1)
    return Δ1 ∪ Δ2</code></pre>

落地约束：

- consistent(S) 不是简化规则检查，而是同一个 CSP 内核的**可行性-only**求解：忽略软成本和 top-k，maxSolutions=1。
- C 只放用户可放松硬约束，并按放松优先级稳定排序。B 放课程互斥、时段事实、已有课表和学校规则；若 B 自身不一致，是输入数据错误，不应当向用户建议放松学校事实。
- 用排序后的约束 ID 集做 memo key。利用单调性缓存：已知子集无解则其超集无解；已知超集可行则其子集可行。
- 对每个 oracle 调用设置剩余截止时间和节点上限。oracle 超时时，解释状态为 EXPLANATION_UNKNOWN，不能说冲突核已极小。
- QuickXplain 理论返回的是按包含关系极小的 conflict，并在偏好顺序下 preferred；它不承诺全局 cardinality 最小的唯一解释。W3-02 验收应写成「极小冲突核」，不要写成「唯一最小原因」。
- 返回前再做一次防御性验证：对核中每个约束 c 测试 core - {c} 可行。验证失败属于求解器 bug，不进入用户文案。

放松建议只从冲突核类型生成，例如：降低学分下限、移除某个必选、允许一个硬时间过滤例外、增大通勤缓冲、允许容量未知候选或重新包含已知满员候选。所有建议都只是草稿编辑建议，不能自动改约束，更不能自动提交选课。

### 5.6 替代方案取舍

| 方案 | 优点 | 主要问题 | R04 结论 |
|---|---|---|---|
| 自定义位集 CSP + 分支定界（推荐） | 纯 Kotlin JVM；完全控制传播、预算、确定性 tie-break、证据引用和 QuickXplain oracle；200 候选的位集内存很小 | 需要自行实现并证明正确性；最坏情况仍指数 | 首期采用，配套独立 verifier 与合成基准 |
| OR-Tools CP-SAT | 成熟通用求解器；整数约束和状态语义清晰；可作为对照 | Android 运行时依赖与包体需另行评估；解释层仍需自建；首期增加不必要供应链风险 | 不进首发运行时；可在开发机测试中作为交叉校验 oracle |
| 通用 MIP/branch-and-bound 求解器 | 优化下界强、理论体系成熟 | 需要把课程互斥、周次/通勤约束大量线性化；外部依赖更重；解释仍缺失 | 不适合首发 Android 本地沙盘 |
| 元启发式（局部搜索、遗传、模拟退火） | 大规模全校排课常用，易于快速得到可行解 | 不能证明无解或最优；输出质量不稳定；冲突解释仍要另做 | 可作为初始 incumbent 的构造启发，不作为唯一求解器 |

这个取舍与课表文献不矛盾：全校排课问题规模大、变量含义不同，往往需要元启发式；本项目是个人从最多 200 个候选班中挑少量课程，约束传播和分支定界有机会在交互预算内完成，同时保留无解证明和解释能力。

## 6. 复杂度与主要风险

| 项 | 规模/复杂度 | 风险 | 缓解 |
|---|---|---|---|
| 时间位集预处理 | 无序候选对 O(n(n−1)/2·H/64)；n=200,H=1680 约 54 万字级比较 | 很低 | 位集并行；结果缓存到编译模型 |
| 通勤矩阵 | 楼宇对缓存；候选两两检查最坏 O(n²·s²)（s 为每班课段数） | 课段多时预处理增加 | 先按同日同周和间隔窗口剪枝；楼宇对结果缓存 |
| 回溯搜索 | 最坏约 ∏(d_i+1)，指数级；CSP/排课 NP-hard | 稀疏多解且下界弱时爆炸 | MRV/degree、强传播、初始 incumbent、节点/时间预算、诚实部分结果 |
| AC-3 | 一般二元 CSP 文献上界 O(ed³)（e 为约束/弧数量）；完整二元 CSP 中 e=O(n²)，即 O(n²d³) | 简单实例上维护成本可能超过收益 | 首期默认前向检查 + 学分传播；AC-3 作为可基准开关 |
| top-k | 未集满 k 前上界弱；近似重复方案多 | 搜索前期剪枝少 | 构造式种子方案、确定性 tie-break、必要时加多样性约束 |
| QuickXplain | oracle 调用数随冲突大小增长；每次调用本身可能是指数搜索 | 无解解释比正向求解更慢 | 聚合用户级约束、memo、预算保留、验证极小性、超时诚实化 |
| Android 性能 | 开发机结果不能等同真机 | 低端设备可能慢 | 单线程纯 JVM、限制内存、记录节点数；未真机验证不标 DEVICE_TESTED |

**稀疏多解实例是基准必须覆盖的风险**：直觉上冲突越密越难，但密集冲突也会让前向检查更快清空值域；相反，稀疏实例几乎不触发失败，若软成本下界弱，分支定界会遍历大量可行组合。因此 benchmark 不能只生成“越密越难”的夹具，必须把可行解密度作为独立维度。

## 7. 合成基准设计（50 / 100 / 200 候选）

### 7.1 固定生成维度

所有实例用固定种子生成，并序列化为 CanonicalJson 夹具，记录 SHA-256；实现 W3-02 时再填入实际哈希，本文不虚构。

公共维度：

- 学期网格：20 教学周 × 周一到周日 × 12 节；节次时间由显式作息表给出，不写死 07:00 或某个学校作息。
- 教学班课段分布：
  - 55%：每周两次、每次 2 节，周次 1–16；
  - 20%：一次 2 节讲授 + 一次 3 节实验/实践；
  - 15%：单周或双周 2 节；
  - 10%：短学段（如 9–16 周）或周末块。
- 地点：12 栋教学楼、2 个校区。楼间步行矩阵包含 0/5/10/20/45 分钟档；跨校区为 45 分钟或「课间不可达」。
- 已有占用：4 门固定课程或考试，占 8 个两周节块；所有实例共享，模拟真实个人课表。
- 容量：约 8% 已知满员、12% 未知、其余已知有余量。容量只是过滤/解释维度，不伪造实时名额。
- 软权重固定为整数毫分：早第一节 +15，晚课后段 +10，空档每小时 +6，跨楼每分钟 +1，每日超过 8 节每节 +12。数值只是基准负载，不是产品默认值。
- 种子：核心回归用 20260301..20260305；快速门禁先用第一个种子，全量门禁跑全部。

### 7.2 规模表

| 夹具 | offering 结构 | 候选数 | 用户目标 |
|---|---|---:|---|
| S50-base | 10 个 offering × 5 班；4 个必选、6 个可选 | 50 | 必选课全部选择；总学分范围约为必选学分 +5 到 +8（即通常再选 2–3 门） |
| S100-base | 16 个 offering；12 个 ×6 班 + 4 个 ×7 班；5 个必选、11 个可选 | 100 | 同上，目标范围按必选学分 +5 到 +8 |
| S200-base | 25 个 offering ×8 班；6 个必选、19 个可选 | 200 | 同上，目标范围按必选学分 +5 到 +8 |

班型数量必须精确等于规模；多出的班级按固定顺序轮询分配到 offering，避免随机漂移改变总数。

### 7.3 难度族

| 难度族 | 生成规则 | 测量的弱点 |
|---|---|---|
| medium-planted | 先植入一套无冲突、满足学分和通勤的参考解，再生成替代班；候选集中在常见白天时段 | 核心功能与常规性能 |
| sparse-many-solutions | 课段更均匀散布，冲突率低、可行解多 | 分支定界下界是否太弱；top-k 是否爆炸 |
| dense-conflict | 70% 候选落入少量热门时段，冲突率高 | 前向检查/弧一致性是否传播有效；是否过早清空值域 |
| near-infeasible | 在可行基准上做最小扰动，使 2–4 条用户级硬约束共同导致无解 | QuickXplain 是否找到正确小核，而不是把全部约束列为原因 |
| uncertain-data | 周次、楼宇或容量按固定比例未知 | 诚实降级、保守冲突和 UI 解释，不用作性能硬门禁 |
| cross-campus | 参考解附近加入跨校区相邻课段 | TravelTimeMatrix 与课间缓冲是否正确 |

建议门禁矩阵：

- PR 快速层：S50/S100/S200 × medium/dense 各 1 个种子 + S50 near-infeasible。
- Android 全量层：三档规模 × medium/sparse/dense × 5 个种子；三档 near-infeasible × 5 个种子。
- 正确性层：uncertain-data 与 cross-campus 不为性能设阈值，但必须通过语义断言。

### 7.4 夹具验收不变量

每个合成实例必须可独立校验：

1. planted 实例确实至少有一套满足全部硬约束的参考方案；该参考方案只用于生成器自检，不提供给求解器。
2. 候选总数精确为 50/100/200；offering 数、必选数、学分范围与夹具元数据一致。
3. 生成器两次运行输出 CanonicalJson 逐字节一致。
4. 所有 ClassSlot 节次合法，周次在 1..20；未知周次只在 uncertain-data 族出现。
5. 无解族必须附机器可读 expectedCoreType（例如「两个必选互斥」或「学分上下限矛盾」），防止 QuickXplain 用无关约束凑解释。

## 8. “50 个候选小于 2 秒”的可行测量方式

### 8.1 计时边界

验收时间必须从调用 TimetableSolver.solve 前开始，到以下任一结果完整生成后结束：

- 5 套方案完成排序并附成本分解；或
- 无解证明完成且 QuickXplain 冲突核/放松建议生成；或
- 明确的预算耗尽状态生成。

因此计时包含编译、冲突矩阵、传播、搜索、排序和解释，不允许只测纯搜索内层。建议内部给求解器传入 1900ms，预留 100ms 给结果装配和日志；外部硬门限仍是 2000ms。

### 8.2 双层测量

1. **冷启动门禁**：每个夹具在新 JVM 或至少未预热该夹具编译缓存的状态下运行一次。记录 elapsedNanos、节点数、传播次数、内存峰值、结果完成状态。冷启动模拟用户第一次点击沙盘。
2. **稳态回归**：用 JMH（或等价的严格 harness）单线程测量。建议 3 个 fork、每 fork 3 次预热、5 次测量；报告 mean/p50/p95/max。JMH 用于发现回归，不替代冷启动门禁。

### 8.3 50 候选验收口径

建议按严格口径写入 W3-02：

- S50 × medium/sparse/dense × 5 seeds 的可行实例：每一次冷启动都小于 2000ms，且 completion 不是 BEST_FOUND_BUDGET_EXHAUSTED；全量报告 p50/p95/max。
- S50 near-infeasible × 5 seeds：总时间小于 2000ms，返回极小冲突核，且核逐条放松验证通过。
- 若某个稀疏实例超时，允许工程上调整权重/下界后重测，但不允许删除该难例；必须在 PR 中说明。
- 内部目标建议 p95 小于 750ms：给低端 Android 设备、后台负载和后续功能增长留余量。这个内部目标不是 DEVICE_TESTED，只是开发机工程余量。
- 记录节点数和传播次数。即使耗时偶然通过，节点数数量级异常也说明下界或传播存在风险。

### 8.4 环境控制与隐私

- 测量只在开发机执行，使用 $CIS_DEVBOX / $CIS_CAMPUS_ROOT 指代环境；仓库、日志摘录和汇总不写真实地址、账号或绝对路径。
- 单线程运行；算法不得用并行流或依赖开发机多核规模掩盖单核性能。开发机 x86 与 Android ARM 性能不同，门禁结果只证明满足 W3-02 的工程验收，不证明真机体验。
- 固定 JVM 参数与输入版本；基准输出写入门禁日志，日志路径在汇总中一律使用 <campus-root>/logs/... 形式。

## 9. W3-02 / C12 验收测试清单

### 9.1 求解正确性

- [ ] 相邻节次（如 1–2 与 3–4）不冲突；共享任一节次冲突。
- [ ] 单周/双周无共同周次不冲突；共同周次任一天重叠才冲突；周次未知按可能冲突并标不确定。
- [ ] 同一 offering 不会同时出现两个教学班；必选 offering 不会 SKIP。
- [ ] 与已有课表、考试、个人日程重叠的候选被排除或使分支失败，并能追溯到占用事件。
- [ ] 学分等于上下限边界时可接受；超出 0.1 学分也不可接受（用整数毫学分比较）。
- [ ] 课间跨楼不足、跨校区不可达时候选组合被拒绝；楼宇未知时输出不确定证据，不默认可达。
- [ ] 所有返回方案经独立 verifier 重算后满足全部硬约束，成本分解与总成本一致。
- [ ] top-5 去重、确定性排序；同输入同种子多次运行逐字节一致。
- [ ] 预算设为极小值时返回预算耗尽/未知，不误报无解；没有找到方案与证明无解在 API 中可区分。

### 9.2 QuickXplain / 解释

- [ ] 两个必选课程只有互相冲突的教学班时，冲突核只包含这两个必选约束及必要证据，不包含无关学分约束。
- [ ] 学分下限高于最大可达时，核包含学分下限与相关必选/课程集合；逐条移除后可行。
- [ ] 无关硬过滤不会出现在核中；preferred ordering 稳定且有测试。
- [ ] oracle memo 命中不改变结果；一致性 oracle 超时时解释状态为未知。
- [ ] 防御性极小性验证：对核中每个约束 c，core - {c} 可行。
- [ ] 放松建议只是建议，不自动修改草稿或约束，且不包含任何提交动作。

### 9.3 架构、隐私与产品边界

- [ ] :core:solver 为纯 JVM，无 Android Framework、网络、Cookie、学号或密码依赖。
- [ ] 输入候选和输出解释保留 DataProvenance / 来源引用；未知容量、未知周次、未知通勤不会被改成确定事实。
- [ ] 身份作用域复用或显式桥接 SchoolAccountScope；不同 Profile 的求解草稿不串用。
- [ ] 求解结果只写入 :core:selection 草稿；测试中断言不调用 SelectionWritePort。
- [ ] 未在真机或真实学校账号验证前，PR 和能力矩阵不标 DEVICE_TESTED / SCHOOL_VERIFIED。

## 10. 给 W3-02 的实施建议

1. 先实现独立 verifier 和编译模型，再实现搜索；verifier 用于所有基准与解释测试，避免求解器“自证正确”。
2. 第一版只做前向检查 + 学分界传播 + 简单可接纳下界；把 AC-3 留作可开关实验，避免过早优化。
3. 在同一提交链中加入 synthetic generator、固定夹具、冷启动 harness 和 JMH 回归，不要先合并算法后补性能证据。
4. TravelTimeMatrix 先定义接口与假实现，跨校区不可达语义优先；真实路网接入可以后续替换，不影响求解器测试。
5. 无解解释按“小约束集 + 验证极小性”实现；不要暴露 constraint solver 内部两两冲突 ID 给用户，UI 应展示课程、周次、节次和可放松设置。
