# R02 端侧中文 OCR 选型调研

> 日期：2026-11-26（Asia/Shanghai）
> 范围：只读调研；不改业务代码。本文全部结论在获得真机/模拟器证据前保持 `UNVERIFIED`，不得标 `DEVICE_TESTED` 或 `SCHOOL_VERIFIED`。
> 方法：阅读官方文档、许可证、模型卡与公开构件；对公开 AAR / 模型做静态 zip 与 ELF 测量。**没有在本机运行 Gradle、模拟器或 OCR 推理**。

## 0. 结论（推荐默认实现）

**推荐默认：PaddleOCR PP-OCRv6_tiny ONNX + `onnxruntime-android:1.21.1`，以 PaddleOCR 官方 `deploy/ppocr-android` SDK 为参考实现；但不要原样引入其 `com.quickbirdstudios:opencv:4.5.3` 依赖。**

理由按优先级排列：

1. **许可证与隐私最符合本项目**：PaddleOCR 代码和 PP-OCRv6 ONNX 模型卡均为 Apache-2.0；ONNX Runtime Android 的 Maven POM 声明 MIT；模型与推理全部可离线，不依赖 GMS，也没有 ML Kit 那样的 SDK 指标回传条款。
2. **唯一找到“印刷中文 + 屏幕”分项数值的候选**：PaddleOCR 内部基准中，PP-OCRv6_tiny 的检测印刷中文 Hmean 为 **93.1%**，识别印刷中文准确率 **86.7%**、屏幕类别 **71.2%**；PP-OCRv6_small 分别为 **94.2% / 90.5% / 79.7%**。这是厂商自建基准（证据 B），不是独立横评，但至少直接覆盖目标场景。
3. **Android 工程形态匹配**：官方示例是 Kotlin 2.1、minSdk 26、Jetpack Compose、SDK/Demo 分离，项目本身为 Kotlin 2.1、minSdk 31，集成层级匹配。
4. **16 KB 页兼容可控制**：`onnxruntime-android:1.21.1` 的 arm64/x86_64 `.so` LOAD 对齐为 `0x4000`；但官方示例使用的 QuickBird OpenCV 4.5.3 仍为 `0x1000`，不满足 Android 15+ 16 KB 页设备要求，必须替换或移除。

**默认模型档选 tiny，不选 small 的原因**：tiny 模型文件合计 6.24 MB（未压缩），small 合计 31.04 MB（未压缩）。当前项目发布的是单个 universal APK，不能把 25 MB 级差量轻易转嫁给所有用户；OCR 结果按 P3 必须“预览 → 修正 → 确认”，tiny 的精度/体积平衡更适合作为默认。small 可作为后续“高精度包”或用户显式下载项，不作为首版默认。

### 首版实现红线

- OCR Port 必须保留原文图片/裁剪区域、逐行置信度、模型版本、模型 SHA-256、识别时间和 `DataProvenance`；识别结果一律 `UNVERIFIED` 或派生级别，用户确认后才能写日程/药品/资料。
- **不得直接引入 `com.quickbirdstudios:opencv:4.5.3`**：其 arm64-v8a 两个 `.so` 的 ELF LOAD 对齐均为 `0x1000`，而 Android 官方要求 target Android 15+ 的 64 位应用支持 16 KB 页；并且它会给 universal APK 增加约 53.7 MB 压缩原生库。首版优先用 Android Bitmap/Canvas/矩阵裁剪重写必要图像操作；若确实需要 OpenCV，必须换用自行验证过 16 KB 对齐的当前 OpenCV/opencv-mobile 构建。
- 当前仓库没有 `abiFilters` 且发布单 APK；[v0.20.23 release APK](https://github.com/yellowpeachxgp/day-in-school/releases/tag/v0.20.23) 已为 52.58 MB。若继续 universal APK，ONNX Runtime 全 ABI 体积是主要成本；推荐把默认实现与 ABI 策略一起落地：用户安装包至少拆出 arm64-v8a，x86_64 只用于开发/模拟器测试包。若发布流程坚持单个 universal APK，则不能直接按当前 ONNX 依赖落地，必须先做 Paddle-Lite/reduced runtime 体积 spike。
- 官方说明 PP-OCRv6_tiny 档不支持完整日文（为避免输出层过大）；本场景不是阻塞项。若后续需要日文或更高准确率，再评估 small。

## 5. 推荐落地形态（供 W2-04 使用，不在本卡实现）

1. 在 `:core:textextract` 定义 `OcrEnginePort` 与数据模型：输入图片 hash、模型名/版本/SHA-256、逐行 box/text/confidence、耗时、错误类型、`DataProvenance`；不暴露 Paddle/ONNX 类型给上层。
2. 默认 adapter：`PaddleOcrOnnxEngine`。直接借鉴官方 `ppocr-android` 的检测预处理、DB 后处理、透视裁剪、识别预处理、CTC 解码；把 OpenCV 依赖替换为 Android Bitmap/Canvas/Matrix 或经 16 KB 验证的 OpenCV 构建。
3. 模型随 APK bundled：`PP-OCRv6_tiny_det_onnx/inference.onnx`、`PP-OCRv6_tiny_rec_onnx/inference.onnx`、`inference.yml`。记录 HuggingFace/BOS 来源和 SHA-256；本次静态调研下载的 det SHA-256 为 `193bab7a04fca699a6c82e6abb5b81bdb28177f0abd4062552b04908dafb19f8`，rec SHA-256 为 `9ef676d6ed3c88256a2d92c640c44f25b0c40947e111b14b8be8f594091563e6`；落地时必须固定版本并重新核验，不把模型下载放到首次使用关键路径。
4. 线程与资源：默认 CPU、1–4 线程可配置；识别在后台 dispatcher；`close/release` 与 Profile 切换绑定；不得在日志中写图片内容或识别出的个人敏感文本。
5. 精度门禁：用真实校园通知截图、课表截图、校医院药品公示拍照、深色/浅色模式、200% 字号、倾斜拍照建立小规模匿名评测集；至少报告 CER、行召回、字段级可用率和人工修正率。未通过前只标 `UNVERIFIED`。
6. 体积门禁：W2-04 PR 必须给出 universal APK 与 arm64-only/split APK 的实际 before/after 对照；默认预算按 split 后 arm64 约 12.16 MB 评估。若坚持 universal 且增量超过 25 MB，优先评估 Paddle-Lite 转换或自定义 reduced ONNX Runtime/MNN，而不是静默接受。

## 6. 不确定项与后续验证清单

1. **没有独立跨引擎中文截图 benchmark**：PP-OCRv6 数字来自 PaddleOCR 自建内部基准；“屏幕”是否等同 Android 应用截图而非拍屏/复杂屏幕场景不确定。必须用本项目语料复测。
2. **ML Kit bundled 的无 GMS 兼容边界不明**：官方文档只明确静态链接和离线可用，未直接承诺在所有无 GMS Android 设备运行；且仍有指标回传和专有许可。
3. **PP-OCRv6 tiny/small 的真实设备功耗和内存未知**：官方 Android 示例有 GM1900 速度样例，但未注明模型档，也不是本项目设备矩阵。
4. **ONNX Runtime 全量包偏大**：1.21.1 已 16 KB 对齐但 universal 成本高；reduced build、MNN 或 Paddle-Lite 都是后续优化方向，当前证据不足以替代官方 ONNX 路径。
5. **Paddle-Lite v5/v6 模型转换未验证**：v2.14-rc runtime 对齐和体积很好，但 PP-OCRv6 没有官方 Paddle-Lite Android 指南；不能因此把它列为默认。
6. **许可证合规动作未完成的方面**：实施时需在 THIRD_PARTY_NOTICES 中加入 PaddleOCR、模型版权归属、ONNX Runtime MIT、可能的 OpenCV/ncnn/Tesseract 通知；若使用转换模型，保留“converted/repackaged from PaddleOCR”的显著说明。
7. **字体/字典资源**：PP-OCRv6 的 rec `inference.yml` 内含字符表并随 Apache-2.0 模型卡分发；若改用 RapidOCR 独立 dictionary/fonts 资源，需要逐项重新核查，因为 RapidOCR 明确说 dictionary/fonts 不在其模型许可声明覆盖内。

## 7. 最终建议

默认采用 **PP-OCRv6_tiny ONNX + ONNX Runtime**；把 **ML Kit bundled** 只作为可选参考/对照，不作为默认；把 **Paddle-Lite PP-OCRv3 slim** 登记为后续体积优化 spike；排除直接内置 RapidOcrAndroidNcnn 2023 预编译包和 Tesseract 作为首版默认识别器。

该建议满足 D1/D3 的保守隐私方向：端侧、离线、无账号、无云端密钥、无 OCR 内容上传；同时避免把 OCR 输出当作事实，必须经用户确认后才进入 Vault/Timeline。
