## 审查时发现的问题与当前状态

1. **教务凭据可还原存储：源码已修复。** 新凭据写入 `noBackupFilesDir` 的 Keystore AES-GCM envelope；旧学号/Base64 在同一迁移流程中回读成功或要求重登后删除。真机 Keystore 失效恢复仍待验证。
2. **凭据及 Cookie 越域风险：源码已修复。** 认证 POST 仅允许精确 CAS 登录路径；每次跳转校验 HTTPS、host、端口和用户信息；教务与 CAS 使用独立 Cookie 容器。合成测试覆盖伪域名、userinfo、端口、明文和片段攻击。
3. **非完整快照覆盖历史：源码已修复。** 成绩/考试使用完整分页读取；只接受有终止证据且通过总数、页数、去重和页循环校验的快照。部分失败保留旧数据，确认空快照可以清空。
4. **身份不稳定：源码已修复。** 成绩和考试改用作用域化 SHA-256 复合键；真正无法区分的记录抛 `AMBIGUOUS_IDENTITY`，不再使用响应数组下标。
5. **无时间课程被制造时间：源码已修复。** `sjkList` 课程保存为独立待排记录，显示原始周次，不进入课表 occurrence 或提醒。
6. **模型名称误导：兼容层仍待清理。** 新增独立 `SchoolId`/`SchoolProfile`，但旧 `StudentProfile.schoolId` 仍保留历史学号语义，消费者迁移完成前不能把它用于学校作用域。
7. **无损升级缺少证据：本地合成证据已补齐。** v4/v5 schema 已提交；Robolectric 测试实际创建 v4 SQLite、执行 migration、比较全表摘要，并验证中断回滚和重复打开。真实旧用户库与设备升级仍未测。
8. **发行签名不严格：源码与工作流已修复。** 默认口令已删除，无正式密钥时只构建 unsigned；正式发行要求完整 secrets，并验证 APK 证书、非调试证书、SHA、commit 和版本。
9. **“已实测”缺少证据：边界仍保留。** 本轮验证只标记为构建/Debug 与合成 SQLite 测试；没有连接设备或授权学校账号，因此不提升到 `DEVICE_TESTED` 或 `SCHOOL_VERIFIED`。

## 本轮不能仅靠本地源码证明的边界

- 九类教务的学校级登录、验证码、分页总数与官方数据一致性，需要相应学校的授权账户和网络；合成夹具只能证明处理逻辑。
- Android 12–16、多厂商 ROM、锁屏一夜、Doze、重启、组件缩放、TalkBack 和性能门槛需要设备或相应可复现环境；模拟器结果需明确标识。
- 已发布 APK 的正式签名身份、旧版原位升级、GitHub 发布 secrets 可用性、正式渠道动态代码政策和外部地图瓦片许可需要独立核查。
- 上游 `zhengfang-apk` 的版本、许可证及具体文件实现须锁定 SHA 后另行核查；本分析没有从 GPL 项目复制代码。
- 旧用户真实库应使用经授权且脱敏的数据或保真合成数据库；未经运行 migration，不能宣称“无损迁移通过”。

上述条件不阻止继续编写可验证的离线功能、测试和安全基础设施；但会限制发布措辞与能力启用，必须在最终交付中保留。

## 集成过程新增的契约与真实入口

以下记录描述本次基线之后已经加入的源码，不能反向覆盖上表的基线结论：

- `UniversalCampusModels.kt` 提供独立学校/校区/账号/Profile 标识、作用域、九类协议类型、逐能力证据与可用状态、来源、错误和快照完整性。九类枚举只解决类型表达，不代表九个适配器完成。每校可定义多个同协议教务实例，使用独立 `systemId`。
- 能力可用需要 `providerSupports && verifiedForAccount && userConsent && prerequisitesReady`，且显式状态允许启用；撤销、未开放与不支持优先阻断。源码、模拟、设备、学校、发行证据独立展示，不能从目录浏览推断已授权。
- `SchoolDirectory` 为纯 JVM 离线目录，提供按稳定 ID 查询、中文/英文/别名/显式拼音和首字母搜索、省市/协议筛选、拉丁词单次编辑纠错，以及本地学校配置覆盖。当前只收录已有实现的河南工业大学，采用 `SOURCE_CONFIRMED`；不生成其他学校适配或学校实测日期。
- “我的 → 学校与能力”接入 `SchoolCenterScreen`，可浏览目录、搜索、查看校区、逐项能力与证据、创建独立离线身份并切换 Profile。目录浏览和第二阶段的学校请求分离；未知学校提供既有导入中心入口，不伪造教务适配。
