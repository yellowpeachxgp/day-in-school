# 云端会话修复验收

旧版在 DataStore 中保存的原文令牌被新版 Keystore 密封读取直接拒绝；界面绑定信息仍在，实际提交入口却拿不到凭据。兼容逻辑只处理与当前云账号一致的旧格式令牌，先加密成功，再在身份锁内条件替换。其他账号、缺少绑定、加密失败均不发送原文。现有数据库 schema 与计划数据不变。

先增加实际 CampusRepository 同步入口回归，旧代码因会话过期失败；修复后旧令牌续期、密封回读和仓库重建均通过。另覆盖原有档案、后来添加档案，以及无绑定或不同账号零网络请求。Robolectric 使用内存密钥端口与真实 AES-GCM，不代表硬件密钥验收。

Android 16 ARM64 模拟器通过 CloudSessionDeviceTest：真实 Android Keystore、Room、DataStore，通过 HTTP 连接真实 Cloud handler，旧版凭据升级、轮换、仓库重建、同步和创建明天待执行计划完整通过。服务只监听本机，不启动学校或资金 worker；验证一条父计划、一条任务、正确目标日期，订单与资金操作均为零。此测试是设备上的仓库入口验收，不冒充真实账号的完整界面操作。

复现设备测试：启动 `node tools/device-tests/cloud-session-server.mjs <隔离Cloud源码目录>`，执行 `adb reverse tcp:18190 tcp:18190`，然后运行 `:core:database:connectedDebugAndroidTest`。必须使用临时设备与假账号，不配置生产环境变量；测试 APK 的明文 HTTP 权限仅存在于 androidTest。

本机完整单元测试、Debug/Release 编译与 Lint 通过；额外档案升级路径继续复测。跨端实际 handler 报价和错误 fixture 已同步至 Cloud 合并提交 618fe02。最终 Lint、CI 和正式签名发行结果以对应工作流为准。

实际学校账号已独立完成只读登录与 40 个自习室查询；未预约、退座或操作资金。用户的 XPeach 账号登录尚需本人在正常登录页完成，因此不声称已用真实云账号创建计划。密码未进入源码、测试、日志或提交。

兼容与回滚：覆盖安装保留 Room 和旧计划，不卸载或清数据。升级前的原文仅在确认归属并加密成功后替换，不要求清账号。回滚到 v0.20.22 仍可读取升级后的密封格式；不回退到明文格式版本，不恢复旧数据覆盖新计划。云服务已先备份，再单写者停机更新，现有签名/KMS/SSO 配置与业务记录逐项保持一致。

复审历史源码证明：v0.20.2 前后来创建的档案（isLegacy=false）同样写入原文云令牌，不能以档案类型限制格式升级。新增该路径失败回归后移除不恰当限制，仍以当前绑定、凭据归属和身份世代锁保护迁移。
