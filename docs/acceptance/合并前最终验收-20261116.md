## 未来日期：学校规则与产品限制分开

校方 [2026-09-03 座位预约规则](https://lib.haut.edu.cn/info/1262/9215.htm) 明确仅可预约当天座位，预约开放为 07:00–21:30。它**没有说明未来日期查询 API 从何时可读**，不能把 07:00 当作查询开放时刻。[2025-04-01 入口通知](https://lib.haut.edu.cn/info/1162/12015.htm) 要求从“云上工大”进入；旧微信入口不能当当前契约依据。

当前 Day 建计划要求目标日期对应的区域、座位结果及明确选择；目标日查询未开放便无法提前选座建计划。这是“学校仅当日预约”的规则与“客户端把实时选座作为建计划前置”的实现共同造成的体验限制。提前保存执行意图并不等于提前向学校预约，但不能把历史布局或今天空座冒充未来空座。

本轮没有改变预约规则。上线前需用户选择：

1. **建议：提前保存未武装草稿**。只保存日期、时间、区域/座位偏好，明确标记目标日可用性未知；开放后重新查询并让用户确认身份、参数、价格，再武装。
2. 历史布局作为候选偏好。显示来源日期和未知可用性，开放后只读校验；明确“不可用时停止”还是允许哪些替代座位。
3. 仅指定区域/偏好，到官方窗口内自动匹配。需先确定替代策略、失败处理和是否需要再次确认；这是新增授权行为，不能默认为用户同意。

要补齐查询开放时点，需要校方关于“何时可以查询哪一天座位”的明确说明，或获授权的隔离只读会话；不需要向对话发送密码。

## 迁移、兼容与回滚

本轮额外修复不再增加 Room 版本，但整个 PR 是 Room **8→9→10**：调课 moveId/moveRole、逐行不可复用 mutationToken、考试原学期来源与修复审计。旧行无权威来源时保留/待核对，不根据日期猜学期；旧模糊调课不自动删除疑似目标。迁移测试使用真实临时 SQLite/Room，不代表真实用户数据量或设备迁移验收。

UI 新的身份参数为可选项，旧内部调用保持源码兼容；云端创建已成功或未知时保留原 owner 和回执，不能因切号/过期确认而把它伪装成失败并换键重发。报价坏数据、未知金额/单位、未知存储错误均保守失败，不静默变价或自动真实重扣退款。

升级前应在应用停止时备份全部账号数据库（连同 WAL/SHM）、注册表、DataStore 与会话存储，记录版本。旧版 Room 8 不能直接读取 Room 10；禁止靠清库或破坏性降级回滚。优先前向修复；恢复旧备份前须明确会丢失升级后的本地变更，并先核对云端预约/资金状态。Android Keystore 不能当作可随 JSON 导出的密钥；重装后可能需要重新授权，不能承诺凭据可跨设备恢复。
