## 上线判断和仍需决定的事项

修复后的候选适合受控验收/灰度，暂不作真实预约与资金全量开放的无条件通过结论。理由是正常业务闭环的设备联调与部署准备尚未完成，不是要求继续堆叠假想风险的防御分支。

- 需要一个获授权的隔离学校/SSO 测试会话或等价测试入口，完成设备上的查询→选座→报价确认→执行结果闭环；本轮不借真实预约或扣退款补齐。
- 未来日期查询未开放时，当前客户端不能提前选座建计划。用户需要决定是否采用“提前只保存未武装草稿、可用性未知，开放后查询并再次确认”的方案；本轮不改变规则，也不把历史布局当未来空闲。
- 线上旧绑定中 5 个需要重新授权；单写者、独立 supervisor、受限权限备份和恢复顺序沿用 Cloud 验收报告，在上线窗口实际落实。不存在多副本写入安全承诺。

本轮不改 Room schema、数据库迁移或报价 schema，不需要新增迁移。整个 PR 的 Room 8→10 和 Cloud 快照升级/回滚边界继续以已有验收报告为准：旧客户端、旧快照和已确认/未知资金不被重写；升级后不可直接用旧程序写新快照，也不可降级清库。未合并、部署、注册账号或操作真实预约与资金。
