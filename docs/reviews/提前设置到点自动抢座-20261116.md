# 提前设置，到点自动抢座（2026-11-16）

用户已明确选择：提前设置好，到点自动抢，不要求目标日再次打开 App 确认。本轮据此落实，取代上一份业务复核中的“草稿还是自动执行”待决定事项。基线 Day `68a17c6a10634fdb012e45bb00ee5912db1ce974`、Cloud `7bfceeeb8c603e248da90cc71ac0719e6f6f2fd7`；fetch 与 PR API 确认没有他人新提交，工作区开始时干净。

## 用户看到的行为

- 明天或指定未来日期尚未开放查询时，可点“用今天布局提前选座”，选择自习室和最多三个有顺序的候选座位。
- 页面明确显示布局来源日期和目标日期，提示目标日可用性未知；参考布局不显示空余数量或“空/占”，也不提供仅看空座过滤。今天的原始状态保留，不伪造成未来空闲。
- 开启计划后自动按原目标日期和首选/备选顺序执行，不再要求明天打开页面确认。候选都不可用时不自行换到未选座位或其他自习室。
- 云端模式在手机关机/断网时仍由 Cloud 执行；本机模式仍要求手机联网、闹钟与后台权限就绪。仅到点提醒模式继续明确要求手动操作。
- 创建前的身份/价格确认保持原有规则，已创建计划按创建时同意的价格执行。没有放宽学校预约窗口或授权要求。

## 实现

`LibraryBookingDateState` 独立记录绝对目标日和明确选择的布局来源日。布局只提供偏好名称；`BookingDraftParams`、实际 Compose submitter 和仓库入口始终接收目标日。切换来源会使在途查询和旧报价确认失效，返回目标日重新查询也清除旧选择。今天/明天跨午夜仍更新日期、清空旧结果；明确日期保持固定，参考布局保留其实际来源日。

参考布局可创建定时计划，不能用于“立即尝试”；立即执行的两处实际检查都接到 `prepareImmediateBooking`。没有新增 Room 字段、状态框架或迁移。计划保存的是原有日期、区域和候选偏好，执行器到点按目标日查询。

Cloud 本来已支持提前计划。本轮验证该闭环，并修复了“指定自习室消失却预热其他自习室同号座位”及旧缓存消费的同根路径。跨端契约源固定到 Cloud `3533b922afd74a6a02d99cd26c13f061b9e8f5f0`；实际 handler 的共享报价/错误 fixture 与 Schema 保持一致。
