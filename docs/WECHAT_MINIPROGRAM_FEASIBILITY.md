# Day in School 微信小程序与商业化可行性及范围说明（Issue #20 专项评估）

> **关联需求**：[`yellowpeachxgp/day-in-school#20`](https://github.com/yellowpeachxgp/day-in-school/issues/20) —— 希望推出微信小程序版本，并通过在小程序中接入商业广告维持持续运营；同时指出当前存在同名小程序但功能体验尚不完善。

---

## 1. 原始诉求与产品定位复盘

用户在 Issue `#20` 中提出的核心诉求包含三个层面：
1. **跨平台轻量化访问**：希望在不安装 Android APK 的场景下（例如 iOS 设备、临时查课表/查空教室/查校园地图/查校医院药价），能够通过微信小程序直接使用核心能力。
2. **体验对标主客户端**：希望官方若推出小程序，应保持与 Android 客户端一致的数据准确性（周次校历、调休停课、教室定位、考试安排等），解决现有同名小程序功能缺失问题。
3. **可持续运营模式建议**：建议通过在小程序内接入激励/横幅广告覆盖服务器与维护成本。

---

## 2. 功能范围划分（小程序可承载 vs 必须保留原生端）

由于微信小程序运行在受限的沙箱与微信公众平台合规框架内，且学校内网/教务 CAS/图书馆系统对源站 Cookie、TLS 与域名白名单有严格限制，小程序版本若立项，必须采取 **「只读公共资料 + 已同步快照展示」** 的精简架构：

| 能力模块 | 微信小程序可行性 | 规划实现方式与边界说明 |
| :--- | :--- | :--- |
| **已同步课表 / 考试查看** | 可行（需先在客户端或受控端完成同步） | 小程序通过 `cloud-in-school` OIDC 会话读取用户已同步的课表 JSON/ICS 快照，不直接在小程序前端采集或中转学校统一身份认证明文密码 |
| **校园地图与楼宇/教室检索** | 可行 | 复用 `ClassroomBuildingResolver` 楼宇字典、双校区电子围栏与嵩山路/莲花街自习教室名录 |
| **校医院药品价格公示查询** | 可行 | 纯只读静态公示目录（198 项西药/中成药公示单价与医保政策说明），零隐私风险 |
| **合作社团 / 学科竞赛指南 / 失物招领广场** | 可行 | 直接复用 `cloud-in-school` `/api/v1/campus-content` 与 `/api/v1/moments/*` 公开及受控联系接口 |
| **教务系统直连抓包同步** | **受限（不建议在小程序内直接输入教务密码）** | 微信小程序 `wx.request` 强制校验已备案 ICP 业务域名，无法直连未授权的 `jwglxt.haut.edu.cn`；若由第三方服务器代登教务则涉及教务凭据托管风险。因此教务导入应保留在本地 Android 客户端或通过离线 JSON/ICS 文件导入 |
| **Android 桌面小组件 / 精确闹钟 / 本地 07:00 零费用抢座** | **仅限原生端** | 依赖 Android `AppWidgetManager`、`AlarmManager` 与本地加密凭据仓 (`AcademicCredentialVault`)，小程序受平台后台生命周期限制无法替代 |

---

## 3. 账号、凭据与隐私安全红线

1. **绝不在小程序端明文收集或违规托管教务密码**：
   - Android 客户端的免费课表同步与免费本地抢座均在设备本地 AES-256-GCM 加密仓 (`AcademicCredentialVault`) 中完成，不经过任何第三方服务器。
   - 小程序端由于无法直接跨域请求学校内网/CAS 接口，绝不能为了图省事将小程序做成“明文上传学号密码的代爬中转站”。
2. **云端委托最小范围原则**：
   - 仅当用户主动开启 `cloud-in-school` 云端托管服务并签署明确版本化授权同意书 (`consent_id` + `auth_version`) 时，才在云端隔离保存对应绑定凭据，且支持随时一键撤回与级联终止。

---

## 4. 商业化与广告接入原则评估

针对 Issue `#20` 中提出的“通过小程序广告维持运营”的建议，经工程与产品合规评估，确立以下原则：

1. **核心工具链路零广告干扰原则**：
   - 今日课表、周课表、上课提醒、考试倒计时、紧急教室导航、校医院药价公示等高频刚需页面，**严禁插入开屏广告、弹窗广告、诱导点击横幅或强制激励视频**，避免破坏学生在赶课、备考场景下的专注体验。
2. **成本控制优先于广告变现**：
   - `day-in-school` 采用本地优先（Local-First）架构：95% 以上的计算（课表解析、GPA 计算、地图矢量渲染、药价检索、本地闹钟与本地座位预约）均在用户手机本地免费完成，服务器仅承担极轻量的社区目录、失物招领与可选云端定时任务，单用户边际服务器成本极低。
3. **若未来引入自愿支持机制**：
   - 仅考虑非侵入式的开源赞赏或云端托管算力配额，不在工具界面植入第三方商业广告 SDK，亦不向任何广告商共享学生学籍、课表或位置数据。

---

## 5. 维护成本结论与阶段路线

1. **当前阶段结论（受外部主体资质与备案阻塞，暂不作为主交付端）**：
   - 微信小程序上线并配置 `request` 合法域名，前提是具备已完成微信认证的小程序主体、ICP 备案域名及专项内容合规审查。
   - 在主体资质就绪前，`day-in-school` 聚焦打磨 **Android 原生客户端 + 标准课表互通导出（JSON / Markdown / CSV）+ `cloud-in-school` 开放 API**。
2. **技术就绪度储备**：
   - 本仓库已将核心数据模型（`TimetableInterchangeAdapter`、`/api/v1/campus-content`、`/api/v1/moments/snapshot`）标准化为跨端无状态的 JSON 契约，后续一旦小程序主体就绪，可直接作为纯视图层接入现有 BFF 接口而无需重构后端。
